# 腾讯云 向量数据库：索引怎么选、规格怎么挑，搭建 RAG 知识库前先弄明白这几件事

腾讯云 向量数据库（Tencent Cloud VectorDB）是一个全托管的自研分布式数据库，专门用来存储和检索向量。文本、图片、音频经模型转成一串数字后存进去，查询时它按相似度返回最接近的结果。大模型知识库、推荐系统、问答机器人、以图搜图，都是它的典型用法。

真正让人卡住的通常不是“要不要用”，而是建表时索引类型和相似度度量怎么定、规格买多大、RAG 流程怎么接。这篇按实际决策顺序讲。

## 腾讯云向量数据库到底解决什么问题？

它解决的是“相似性查找”：传统数据库按条件精确匹配，向量数据库在向量空间里找最接近的几条记录。

四个概念过一遍就够用：

- 向量：把文本、图像等非结构化数据转换成一串数字，保留核心特征。
- 向量检索：在向量空间里找“最相似”的数据，属于相似性匹配。
- 索引：为加速检索建立的数据结构，作用类似书籍目录。
- 相似度度量：判断两个向量有多像的尺子。

产品本身是全托管服务，部署、运维、扩缩容由平台负责。官方文档给出的能力包括单索引支持 10 亿级向量规模、百万级 QPS、毫秒级查询延迟；产品页目前写的是单索引千亿级，这个口径差异后面会单独说。底层基于腾讯自研的向量检索引擎 OLAMA，采用 Raft 分布式存储，Master 节点负责集群管理和调度，支持多分片、多副本。资源层级是实例 > Database > Collection > Document，SDK 覆盖 Python、Java、Go、C++。

## 索引类型怎么选？五种索引各有边界

数据量小于 10 万又要 100% 召回，用 FLAT；百万到亿级的通用场景首选 HNSW；亿级以上大规模数据看 IVF 系列；高维超大规模想压存储，考虑 IVF_RABITQ；二进制向量用 BIN_FLAT。

| 索引类型 | 核心原理 | 适用场景 |
| --- | --- | --- |
| FLAT | 暴力比对，精确搜索 | 数据量小（<10万），要求 100% 召回率的基准场景 |
| HNSW | 基于多层图结构快速导航 | 通用首选，百万至亿级数据，平衡性能与召回 |
| IVF 系列 | 聚类思想，缩小搜索范围 | 亿级以上大规模数据，追求存储和计算效率 |
| IVF_RABITQ | 聚类思想与二进制量化 | 亿级超大规模高维向量，高召回率兼顾高倍压缩 |
| BIN_FLAT | 专为二进制向量设计 | 图像二值化特征等二进制数据检索 |

有个默认行为值得记一下：建表时如果不指定索引类型，检索会走暴力搜索。召回是精确的，但速度慢很多，数据量一大就明显。官方文档写明了这一点，实际建表时却很容易漏。

## 相似度度量：尺子选错，结果就偏

度量方式要和向量来源匹配：文本相似度优先余弦；深度学习模型输出的向量常用内积；低维空间衡量绝对距离用欧式距离；二进制向量用汉明距离。

| 相似度度量 | 数值方向 | 适用场景 |
| --- | --- | --- |
| 内积（IP） | 值越大越相似 | 通用场景，尤其深度学习模型输出的向量 |
| 余弦相似度（COSINE） | 值越大越相似 | 文本相似度计算，忽略向量长度 |
| 欧式距离（L2） | 值越小越相似 | 衡量绝对距离，低维空间效果良好 |
| 汉明距离 | 值越小越相似 | 比较二进制向量的差异 |

建表时指定的索引类型和相似度度量，就是之后检索执行的组合。这个组合在建表阶段定下来，等数据写进去再发现不合适，处理成本会高不少。

## 从文档到问答：RAG 知识库怎么落地？

不用自己写文档切分和向量化代码。把原始文档上传到 AI 套件，解析、切分、向量化、入库由平台完成；提问时问题被转成向量，检索出最相关的语料，再和问题一起送进大模型生成答案。

流程拆开是五步：

1. 上传文档。AI 套件支持多种文本文件，包括不好处理的 PDF 图文混排内容。
2. 自动处理。文档解析、信息补充、向量化在套件内完成。
3. 入库。文件和向量化数据都存放在腾讯云向量数据库里。
4. 检索。用户问题经 Embedding 转成向量，在库里做相似性检索，找出相似度最高的语料。
5. 生成。问题加检索到的上下文一起送进 LLM，由模型组织答案。

模型侧，官方教程演示了 DeepSeek、混元、百川等模型的接入方式，按业务需要选就行。Embedding 功能让数据写入和检索自动向量化，不用单独维护向量生成流程；官方称优化 GPU 处理后性能提升 5~10 倍，GPU 资源池按需使用。知识库内容有变化时，可以按需更新库里的数据，存储策略比较灵活；2.0 版本还支持 TTL，稀疏向量检索也已上线。

## 选购前值得确认的几个细节

下面几条都在官方文档里写着，但很容易在选购时被跳过。

- 地域：当前支持北京、上海、广州、成都、上海自动驾驶云、深圳金融、中国香港、新加坡、硅谷，其他地域在规划中。实例新建后不能切换地域，别等上线了才发现选错。
- 默认索引：建表不指定索引类型就走暴力搜索，数据量大时性能差距明显。
- 规模口径：产品文档写单索引支持 10 亿级向量规模，产品页写千亿级。做容量规划时，直接对照你选购的规格页和性能白皮书，别把宣传数字当成承诺。
- 高可用：多副本部署，节点故障和负载变化时仍能运行。
- 存储型别硬扛并发：它的定位是数据量大、QPS 低，高并发场景选计算型更合适。
